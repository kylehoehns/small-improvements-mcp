# small-improvements-mcp agent instructions

## Commands
- Typecheck: `npm run typecheck`
- Test: `npm test` (all) · single file: `npx vitest run test/dates.test.ts` · by name: `npx vitest run -t "trailing"`
- Build: `npm run build` (tsup → `dist/index.js`)
- Run from source: `SI_API_TOKEN=… npm run dev`

## Rules (most-violated first)
- Relative imports use a `.js` extension even though the source is `.ts` (`import { loadConfig } from "./config.js"`). ESM + `moduleResolution: "Bundler"`; the bare or `.ts` form breaks the build.
- This server is **read-only**: every API call is a GET, and it only ever reads the authenticated user's own data. Do not add write/mutation tools or endpoints.
- Tool logic lives in `src/tools/<tool>.ts` as a pure `runX(client, …)` function that takes the `SiGetter` **interface** (not the concrete `SiClient`). `src/index.ts` only registers tools and JSON-serializes results. This is what makes tools testable with stubs — keep new tools to the same shape.
- Tests inject a stub `SiGetter` (or a fake `fetch`) and read fixtures; they never hit the network. Match that pattern for new tests.

## Conventions the code won't tell you
- `test/fixtures/*.json` are **anonymized** captures (real names/emails/free-text scrubbed to `Person N` / `personN@example.com` / placeholders) but keep the live API's shape. Never commit real Small Improvements data here.

## Do not touch
- `dist/` — generated by tsup (built via the `prepare` script on `npm install`). Edit `src/` and rebuild.
